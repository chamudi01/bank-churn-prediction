# Customer Churn Analytics

Streamlit dashboard and reproducible training pipeline for bank customer churn,
built from `notebooks/ChurnModelling.ipynb`.

## Quick start

Requires Python 3.10 or newer.

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 1. put the dataset at data/raw/Churn_Modelling.csv
# 2. train and write artifacts/
python -m churn.train

# 3. launch the dashboard
streamlit run app.py

# optional: tests (use synthetic data, not your dataset)
pytest
```

`python -m churn.train` accepts `--data PATH`, `--out DIR` and `--model NAME`
(forces the dashboard's default model instead of the best cross-validated one).

## Layout

```
app.py                     entry point and navigation
churn/                     ML code, no Streamlit imports
  config.py                schema, paths, risk bands, constants
  data.py                  loading, cleaning, input validation
  features.py              feature engineering as an sklearn transformer
  modeling.py              candidate models and pipeline builder
  evaluate.py              metric and threshold helpers
  train.py                 CLI: trains, evaluates, writes artifacts/
  predict.py               artifact loading, scoring, per-customer effects
dashboard/
  theme.py                 palette, chart defaults, CSS
  components.py            shared UI helpers
  state.py                 cached loaders and guards
  views/                   one file per page
tests/                     pipeline tests (synthetic data only)
notebooks/                 original analysis
artifacts/                 generated by training (git-ignored)
```

## Pages

| Page | Purpose |
|---|---|
| Portfolio overview | Filterable churn rates by geography, age, products, balance, membership |
| Model performance | Model comparison, ROC curves, threshold control with confusion matrix |
| Churn drivers | Permutation importance and response curves by attribute |
| Single customer | Score one profile; see which attributes raise or lower the score |
| Batch scoring | Upload a CSV, validate, score, download |
| Methodology | Data handling, model selection, limitations |

## Differences from the notebook

These were deliberate; expect metrics to differ slightly from the notebook's.

1. **No leakage.** The notebook scaled all rows and computed the high-value
   medians before splitting. Here both are learned on the training split only.
2. **Model selection** uses 5-fold cross-validated ROC-AUC on the training
   split, not the test set. The test set is only for reporting.
3. **"Logistic Regression" and "Ridge" were the same model** (the default
   penalty is L2), so they appear once.
4. **Decision threshold is adjustable.** At 0.5 the notebook's models catch
   roughly 31–49% of churners; the performance page shows the trade-off.
5. Notebook metrics that treat probabilities as regression output (MSE, R²,
   "variance accuracy") are not carried over; they do not describe classifier quality.
6. Open-ended explainers (SHAP, LIME) are replaced by permutation importance and
   one-attribute-at-a-time effects, which work for every model with no extra dependencies.

## Operating notes

- Artifacts are pickled scikit-learn pipelines. Retrain after changing
  scikit-learn or pandas versions, and never load artifacts from untrusted sources.
- Risk band edges (20% / 50%) live in `churn/config.py`.
- The overview page reads `data/raw/Churn_Modelling.csv` directly. If you deploy
  without the raw file, that page shows a notice and the rest still works.
- To add a model, add a factory to `model_factories()` in `churn/modeling.py`
  and retrain; the dashboard picks it up automatically.
